一、项目当前版本说明（请先看）
本项目当前主线已经从旧版“4 类 up/down/left/right”调整为“2 类 left/right”：
- label_id=0 -> left
- label_id=1 -> right

当前采集脚本 realtime_record_trials.py 中：
- 按键 1 选择 left
- 按键 2 选择 right
- Space 开始/结束一个 trial
- Esc 退出

当前键盘映射脚本 emg_udp_to_arrows.py 默认：
- 事件 label=1 -> 键盘 'a'
- 事件 label=2 -> 键盘 'd'

说明：
- 在线推理阶段仍然有一个额外的 rest 类，但它不是训练标签，而是在线门控逻辑生成的“静息状态”。
- 因此：
  - 训练标签是 0/1（left/right）
  - 在线输出标签是 0/1/2，其中：
    - 0 = rest
    - 1 = left
    - 2 = right

--------------------------------------------------
二、环境与前提
--------------------------------------------------
1）采样率必须一致
采集保存 trial 时的 --sfreq、切窗构建数据时隐含的 sfreq、在线推理时的 --sfreq 必须一致。
否则窗口点数、RMS 平滑尺度、特征尺度都会不一致，模型效果会明显变差。

2）通道顺序必须一致
训练与在线推理必须使用完全一致的通道顺序。
例如 config.ini 中 app/channels = 1,2,3,4,5，则：
- 采集保存 trial 时按这个顺序保存
- 训练时默认按 trial 中的通道顺序使用
- 在线推理 realtime_decode_udp.py 也必须按同样顺序拼 [L,C]

3）标签体系必须一致
当前主线仅支持两类：
- left
- right

如果你后续重新扩成 4 类，必须同步修改：
- realtime_record_trials.py
- build_windows_from_trials.py
- train_cnn_4actions_simple.py
- train_svm_emg.py 
- realtime_decode_udp.py
- emg_udp_to_arrows.py

--------------------------------------------------
三、采集并保存数据（trial 级别）
--------------------------------------------------
命令：

python -m epstudiosdk.realtime_record_trials --config .\data\config.ini --sfreq 1000

如果不写 --config，则默认使用脚本同目录下的 data/config.ini。

按键说明：
- 1：当前标签设为 left（label_id=0）
- 2：当前标签设为 right（label_id=1）
- Space：开始/结束一个 trial
- Esc：退出程序（会自动停采集并收尾）

输出：
- 默认会在脚本目录下 records/ 中创建一个新 session 目录：
  session_YYYYmmdd_HHMMSS
- 目录内包含：
  - meta.json
  - trial_0001_label0_left.npz
  - trial_0002_label1_right.npz
  - ...

每个 trial_*.npz 内通常包含：
- emg: [T,C]
- sfreq
- channels
- device_mac
- label_id
- label_name
- saved_at

建议采集节奏：
- 每个动作至少 20~30 个 trial
- 每个 trial 建议 1~2 秒
- trial 间放松 1~2 秒
- 一次 session 内尽量保持动作标准一致
- 电极位置、通道顺序、采样率尽量不要变

--------------------------------------------------
四、多组数据的推荐组织方式
--------------------------------------------------
如果你已经有多组 session 数据，推荐做法不是分别训练多个模型，而是：

1）把多组 session 的 trial_*.npz 合并到一个总目录
例如：
records/
  session_A/
  session_B/
  session_C/
  merged_train_v1/

把 session_A、B、C 中的 trial_*.npz 复制到 merged_train_v1 中。

2）在 merged_train_v1 上统一切窗、统一提特征、统一训练
这样可以保证：
- 所有数据使用同一套切窗参数
- 所有数据使用同一套活动筛窗规则
- CNN 与 SVM 都能基于同一份总数据训练

注意：
- 合并前要先确认各组数据的 sfreq 一致
- 通道数与通道顺序一致
- 标签定义一致（当前应为 left/right）

--------------------------------------------------
五、从 trial 构建训练数据
--------------------------------------------------
命令（推荐）：

python build_windows_from_trials.py --in_dir .\records\session_20260507_merge_jny --write_index --save_features --win_sec 0.20 --step_sec 0.05

常用可调参数（如需要）：
- --win_sec 0.30
- --step_sec 0.05
- --trim_head_sec 0.20
- --trim_tail_sec 0.20
- --rms_smooth_sec 0.02
- --thr_q 0.55
- --active_ratio_thresh 0.65
- --min_window_rms_q 0.00
- --write_index
- --save_features

说明：
本脚本不是简单地“把 trial 全部切窗”，而是会先做活动筛选：
1. 对多通道信号计算逐点 RMS
2. 对 RMS 做平滑
3. 用 trial 内分位数阈值生成 active mask
4. 只保留 active_ratio 足够高的窗口

这样可以减少 trial 前后静息段、过渡段带来的噪声标签。

输出文件（在 session 目录内）：
- X_single_windows.npy
  形状 [N, T, C]
  表示 N 个训练窗口，每个窗口长度为 T、通道数为 C

- y_single_labels.npy
  形状 [N]
  当前标签值为：
  - 0 = left
  - 1 = right

- gesture_to_id_single.csv
  当前通常为：
  left,0
  right,1

- windows_index.csv（当 --write_index 时）
  记录每个窗口来源于哪个 trial、起止位置、active_ratio、mean_rms 等，便于排查数据质量

- X_features.npy（当 --save_features 时）
  形状 [N, F]
  表示每个窗口提取后的时域特征

- feature_names.csv（当 --save_features 时）
  对应特征名列表

--------------------------------------------------
六、查看切窗质量（可选但推荐）
--------------------------------------------------
命令：

python inspect_trial_windows.py --session_dir .\records\session_20260318_161213 --n 5

作用：
- 随机抽取若干 trial
- 画出平滑后的 RMS 曲线
- 画出修剪区间与窗口起点
- 便于观察当前 thr_q、win_sec、step_sec 是否合理

如果你发现：
- 很多窗口落在静息段
- 有效动作段被截得太少
- active 阈值过高或过低

可以回头调整：
- --trim_head_sec
- --trim_tail_sec
- --thr_q
- --active_ratio_thresh
- --min_window_rms_q

--------------------------------------------------
七、训练 CNN 基线模型
--------------------------------------------------
命令：

python train_cnn_4actions_simple.py --data_dir .\records\session_merge_zly --ckpt .\cnn_lru_merge_zly.pth

说明：
虽然文件名还保留 4actions 的旧名字，但当前实际主线可以作为 2 类 CNN 基线来使用。
训练输入来自：
- X_single_windows.npy
- y_single_labels.npy

输出：
- 一个 .pth checkpoint 文件

通常 checkpoint 中会包含：
- model_state_dict
- class_names
- per_window_norm
- mean / std（如果训练脚本保存了）
等信息

建议：
- 不要覆盖旧模型，保留版本号
例如：
  - cnn_v1.pth
  - cnn_v2.pth
  - cnn_merged_v1.pth

八、训练 SVM 模型（新增推荐）
--------------------------------------------------
命令：

python train_svm_emg.py --data_dir .\records\session_20260318_161213 --out .\svm_lr_5channel_0318_4_soft_100data.pkl

说明：

当前推荐时域特征通常包括每通道：

输出：
- svm_emg_v1.pkl

--------------------------------------------------
九、离线评估（支持 CNN / SVM / 融合）
--------------------------------------------------
1）只评估 CNN：

python offline_eval_trials.py --session_dir .\records\session_20260318_145028 --model_type cnn --ckpt .\cnn_lr_5channel_0318_3_soft_100data.pth

2）只评估 SVM：

python offline_eval_trials.py --session_dir .\records\session_20260318_110525 --model_type svm --svm .\svm_lr_5channel_0318_1.pkl

3）评估融合模型：

python offline_eval_trials.py --session_dir .\records\session_20260318_110525 --model_type ensemble --ckpt .\cnn_lr_5channel_0318_1.pth --svm .\svm_lr_5channel_0318_1.pkl --cnn_weight 0.6 --svm_weight 0.4

常用参数：
- --win_sec
- --step_sec
- --trim_head_sec
- --trim_tail_sec
- --vote majority
- --vote meanprob
- --use_file_sfreq

说明：
- majority：对 trial 内窗口预测做多数投票
- meanprob：对 trial 内窗口概率求平均再取最大类

建议：
- 不要只看训练集上的评估结果
- 最好留出一组或几组 session 专门做测试集
- 这样得到的结果更接近真实上线表现

--------------------------------------------------
十、上线：实时推理 -> UDP -> 键盘控制
--------------------------------------------------
步骤 1：先启动键盘映射端

python emg_udp_to_arrows.py --port 5005 --mode tap --cooldown_ms 120 --debug

当前默认键位映射：
- label 1 -> 'a'
- label 2 -> 'd'

说明：
- 这里的 label 1/2 指的是在线输出标签：
  - 0 = rest
  - 1 = left
  - 2 = right

因此默认效果是：
- left 触发 a
- right 触发 d

如果你想改成方向键、WASD 或别的键，修改 emg_udp_to_arrows.py 中的 DEFAULT_MAP。

步骤 2：启动在线实时推理

1）CNN 模式：

python -m epstudiosdk.realtime_decode_udp --config .\data\config.ini --model_type cnn --ckpt "C:\Users\Administrator\Desktop\HMILAB\毕业设计\mid_3instr\epstudiosdk\cnn_lru_3instr_0410_merge.pth" --sfreq 1000 --ip 127.0.0.1 --port_udp 5005

2）SVM 模式：

python -m epstudiosdk.realtime_decode_udp --config .\data\config.ini --model_type svm --svm .\epstudiosdk\svm_lr_5channel_0318_2_soft.pkl --sfreq 1000 --ip 127.0.0.1 --port_udp 5005

3）融合模式（推荐）：

python -m epstudiosdk.realtime_decode_udp --config .\data\config.ini --model_type ensemble --ckpt .\cnn_lr_xxx.pth --svm .\svm_emg_v1.pkl --cnn_weight 0.6 --svm_weight 0.4 --sfreq 1000 --ip 127.0.0.1 --port_udp 5005

在线推理逻辑大致为：
1. WebSocket 接收多通道 EMG block
2. OnlineGate 计算 RMS 包络并做双阈值迟滞门控
3. 只有 active_ratio 足够高的窗口才送入分类器
4. 分类器输出窗口级概率
5. TapEventSmoother 把窗口预测变成 start/end 事件
6. 通过 UDP 发给 emg_udp_to_arrows.py
7. 键盘映射端根据 event start 触发按键

说明：
- 当前推荐游戏控制优先用 --mode tap
- tap 模式下只在 event start 时触发一次按键，抖动会更少
- hold 模式适合需要“按下/松开”语义的控制

--------------------------------------------------
十一、建议的模型使用策略
--------------------------------------------------
1）不是每采一点新数据就立刻重训
更推荐：
- 先积累一批高质量新 trial
- 与旧数据合并
- 重新统一构建数据集
- 训练一个新版本模型

2）当前更推荐“重训新模型”，而不是在旧模型上直接续训
原因：
- CNN 直接用新数据续训容易遗忘旧数据
- SVM 本身也更适合整批重训
- 版本管理更清晰

3）建议的版本管理方式
例如：
- merged_train_v1/
- cnn_v1.pth
- svm_v1.pkl
- cnn_v2.pth
- svm_v2.pkl

这样便于比较不同版本模型效果。

--------------------------------------------------
十二、最容易踩坑的点
--------------------------------------------------
1）config.ini 里 host / websocket_host 不能错
如果配置里还是 localhost，但你的设备服务实际跑在 10.10.10.60 之类的地址上，就会出现连不上接口、请求被拒绝的问题。

2）采样率不一致
训练是 1000 Hz，在线推理却设成 500 Hz，效果通常会明显变差。

3）通道顺序不一致
训练时 channels=[1,2,3,4,5]，在线却换成 [2,1,3,4,5]，模型基本会失效。

4）标签混乱
如果一部分历史数据是旧版 4 类，一部分是新版 2 类，不清洗直接混合训练，会把模型搞乱。

5）融合权重不是越平均越好
建议先从：
- cnn_weight=0.6
- svm_weight=0.4
开始试，再按离线验证结果微调。

--------------------------------------------------
十三、一个推荐的完整流程
--------------------------------------------------
1. 采集多组 left/right trial
2. 把多组 trial_*.npz 合并到 merged_train_v1
3. 运行 build_windows_from_trials.py 生成：
   - X_single_windows.npy
   - y_single_labels.npy
   - X_features.npy
4. 训练 CNN
5. 训练 SVM
6. 用 offline_eval_trials.py 比较：
   - cnn
   - svm
   - ensemble
7. 选择表现最稳的版本上线
8. 用 realtime_decode_udp.py + emg_udp_to_arrows.py 进行实时控制测试

--------------------------------------------------
十四、当前版本一句话总结
--------------------------------------------------
当前项目建议按“2 类 left/right + 在线 rest 门控 + CNN/SVM/融合”来使用。
如果后续要扩成 4 类，请把采集、切窗、训练、评估、在线推理、键盘映射几个脚本同步修改，不要只改其中一个。
